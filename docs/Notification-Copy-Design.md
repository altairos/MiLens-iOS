# MiLens 提醒与通知文案设计

最后更新：2026-08-12

本文是 MiLens iOS 的提醒、通知、页内提示文案母稿。源语言为简体中文；后续本地化以本文的语义、触发条件和占位符为准，不直接逐字翻译代码中的临时文案。

## 1. 文案总原则

- **像一位温柔的记录者**：提醒用户有一段回忆可以看看，不制造焦虑，也不要求用户立刻完成任务。
- **先说发生了什么，再说可以做什么**：标题负责识别场景，正文负责给出轻量动作。
- **不替用户编故事**：只使用真实的日期、宠物名称、用户备注和已存在的照片；不把通用识别结果写成确定的宠物语义。
- **不夸大隐私承诺**：通知只呈现必要信息；不写“绝不丢失”“永远不会离开设备”等绝对化承诺。
- **尊重通知频率**：同一场景只保留一条主提醒；没有有效照片或没有有效日期时不发通知。
- **产品术语统一**：宠物档案、往日回忆、时光机、纪念提醒、领养日、拼豆图纸。

### 长度建议

| 位置 | 建议长度 | 写法 |
|---|---:|---|
| 系统通知标题 | 6–14 个汉字 | 先让用户知道是哪一类回忆 |
| 系统通知正文 | 12–32 个汉字 | 一句话为主，最多两句 |
| Toast / banner | 8–20 个汉字 | 说结果，不解释实现细节 |
| Alert 标题 | 6–12 个汉字 | 直白、可理解 |
| Alert 正文 | 1–2 句 | 说明原因和下一步 |

## 2. 当前已实现的系统通知

当前 `NotifyService` 实际调度两类通知：宠物生日/领养日年度提醒，以及有历史同日照片时的时光机提醒。通知时间为当天 09:00；以下文案可以直接作为现有 `notify.*` key 的内容基线。

### 2.1 生日提醒

触发：宠物档案填写了生日；每年生日当天 09:00。

推荐版本：

| 字段 | 文案 |
|---|---|
| 标题 | `今天是{petName}的生日` |
| 正文 | `去看看{petName}的生日回忆吧。` |

如果通知正文必须复用照片回忆模板，兼容版本为：

| 字段 | 文案 |
|---|---|
| 标题 | `{petName}的生日` |
| 正文 | `今天，给这段陪伴留一点时间。` |

说明：当前实现使用通用标题“纪念日回忆”，并将“{petName}的生日”放在正文中。建议后续将宠物名称和事件类型提升到标题，锁屏上更容易识别，也避免正文读起来像照片备注。

### 2.2 领养日提醒

触发：宠物档案填写了领养日；每年领养日当天 09:00。

推荐版本：

| 字段 | 文案 |
|---|---|
| 标题 | `今天是和{petName}相遇的日子` |
| 正文 | `去看看你们一起留下的回忆吧。` |

更克制的兼容版本：

| 字段 | 文案 |
|---|---|
| 标题 | `{petName}的领养纪念日` |
| 正文 | `今天，回看你们一起走过的这一段。` |

说明：标题不建议写“领养成功”或“命中注定”，以免覆盖用户真实经历；“相遇的日子”适合作为默认温和表达，但保留“领养纪念日”作为明确表达，方便用户理解触发原因。

### 2.3 时光机提醒

触发：未来 7 天内某一天存在历史同日照片；当天 09:00 单次发送。

推荐固定标题：

`{yearsAgo} 年前的今天`

推荐正文模板，按照片是否有备注和是否有关联宠物选择：

| 场景 | 推荐文案 |
|---|---|
| 有宠物名 | `{yearsAgo} 年前，{petName}也在这一天陪着你。` |
| 有宠物名、适合提问 | `{yearsAgo} 年前的今天，{petName}在做什么呢？` |
| 无宠物名 | `时光飞逝，这是 {yearsAgo} 年前的今天。` |
| 有备注 | `时光飞逝，{yearsAgo} 年前的今天：{note}` |

当前四个模板 `asking / companion / flight / flashback` 可以保留为轮换池；建议删除“回忆杀”这类偏网络化表达，避免和纪念日、离世纪念等敏感场景混淆。

空数据规则：没有历史同日照片时不调度；没有备注时不保留冒号；无法关联宠物时使用“这段回忆”或“小宝贝”，不猜测宠物名称。

## 3. 通知权限相关文案

### 3.1 设置页说明

设置项保留：

| 位置 | 文案 |
|---|---|
| 分组标题 | `通知` |
| 开关名称 | `纪念提醒` |
| 说明 | `开启后，生日、领养日和时光机会在合适的时候提醒你。` |

说明不必把“每天 09:00”和“未来 7 天”写得过于技术化；如果需要明确行为，可用辅助说明：

`生日和领养日当天 09:00 提醒；有历史同日照片时，时光机每天最多提醒一次。`

当前 `settings.notifications.footer` 的行为描述是准确的，可以作为开发/测试版本；面向普通用户时建议采用上面的短版。

### 3.2 请求系统权限前的页内说明

标题：`别错过重要回忆`

正文：`允许 MiLens 发送通知，我们会在生日、领养日和有新回忆可看的时候提醒你。你可以随时在系统设置中关闭。`

按钮：`允许提醒` / `暂不允许`

说明：这是产品自己的说明，不替代 iOS 系统权限弹窗；不应写成“打开通知才能使用 MiLens”。

### 3.3 权限被拒绝

当前 key：`settings.notifications.denied.title/message/ok`

推荐版本：

| 字段 | 文案 |
|---|---|
| 标题 | `通知权限未开启` |
| 正文 | `如需接收纪念提醒，请在系统设置中允许 MiLens 发送通知。` |
| 按钮 | `知道了` |

如果页面提供跳转系统设置，按钮改为：`去系统设置`，并保留一个次级按钮 `稍后再说`。不要在用户拒绝后立即重复弹窗。

## 4. 页内提醒、Toast 与 Banner

这些不是系统推送，重点是让用户知道操作结果；不使用感叹号堆叠，不把成功提示写成营销口号。

| 触发场景 | 推荐文案 | 类型 |
|---|---|---|
| 扫描完成，有发现 | `发现 {count} 张值得整理的照片` | 完成提示 |
| 扫描完成，无发现 | `这次没有发现新的照片` | 空结果 |
| 导入完成 | `已加入 {count} 张照片` | 完成提示 |
| 重复照片跳过 | `已跳过 {count} 张重复照片` | 补充提示 |
| 保存宠物档案 | `档案已保存` | Toast |
| 保存编辑照片 | `照片已保存到档案` | Toast |
| 生成拼豆图纸完成 | `图纸做好了` | 完成提示 |
| 导出完成 | `已准备好分享` | 完成提示 |
| 分享取消 | `已取消分享` | Toast，可选 |
| 删除前确认 | `删除这份档案？` / `相关照片记录也会从 MiLens 中移除，系统相册中的原照片不受影响。` | Alert |
| 清理缓存完成 | `缓存已清理，照片和档案未受影响` | 完成提示 |
| 离线备份完成 | `备份已准备好，请选择保存位置` | 完成提示 |
| 恢复完成 | `已恢复 {count} 条记录` | 完成提示 |

数量为 1 时使用“1 张/1 条”；数量大于 1 时使用对应复数形式。数量为 0 时不要显示“已完成”，改用空结果文案。

## 5. 错误与降级提示

错误文案按“三段式”写：发生了什么 → 用户数据是否安全 → 下一步做什么。

| 场景 | 推荐文案 |
|---|---|
| 照片权限不足 | `无法读取照片。请在系统设置中允许 MiLens 访问照片，然后重试。` |
| 扫描失败 | `这次扫描没有完成，已有档案不会受影响。请稍后重试。` |
| 单张分析失败 | `有一张照片暂时无法分析，其他照片仍可继续处理。` |
| 图纸生成失败 | `图纸没有生成成功，原照片未受影响。请换一张照片再试。` |
| 导出失败 | `暂时无法导出这份作品，原内容已保留。请稍后重试。` |
| 备份文件损坏 | `这个备份文件无法读取，现有档案不会受影响。请换一个备份文件重试。` |
| 恢复部分跳过 | `已恢复新记录，已有同 ID 的记录已保留。` |
| 数据库启动恢复 | `MiLens 暂时无法打开本地档案。可以先导出诊断信息，或重建本地数据。` |

不要把内部错误码、路径、模型名称或“SwiftData/Core ML”直接展示给普通用户；这些内容进入诊断日志。

## 6. 规划中但尚未接入的提醒

以下文案可以先锁定语气，但不能在当前版本宣称已经支持。接入前需要同时完成调度、去重、关闭入口和测试。

| 触点 | 触发条件 | 建议文案 |
|---|---|---|
| 相处里程碑 | 第 100/365/730/1000 天 | 标题：`和 {petName} 一起 {days} 天了`；正文：`这段陪伴值得留下一张纪念卡。` |
| 照片数量里程碑 | 达到 50/100/500 张 | 标题：`你和 {petName} 的第 {count} 张照片`；正文：`又多了一页可以回看的日常。` |
| 月度回忆 | 月初生成精选 | 标题：`{month} 月的回忆准备好了`；正文：`看看这个月最值得留下的片段。` |
| 年度回忆 | 年末或用户主动生成 | 标题：`{year} 年的回忆`；正文：`这一年，你们一起留下了 {count} 个片段。` |
| 长期未打开 | 后续如产品确认需要 | 暂不建议默认启用；避免用“你已经很久没来看了”制造负担。 |

里程碑通知的标题应以陪伴和事实为主，不使用“快来”“别错过”“最后机会”等催促词；照片数量里程碑也不要暗示照片越多越好。

## 7. 不采用的表达

| 不建议 | 原因 | 推荐替代 |
|---|---|---|
| `你有一条重要通知` | 信息量不足，像系统告警 | `今天是{petName}的生日` |
| `快来看看！` | 催促、缺少场景 | `去看看这段回忆吧。` |
| `AI 发现了你和宠物的故事` | 超出当前能力事实 | `发现一张可以整理的照片` |
| `照片永远不会丢失` | 绝对化承诺，忽略备份边界 | `档案已保存到 MiLens` |
| `回忆杀` | 网络化且可能触及敏感纪念场景 | `往日回忆` / `这段回忆` |
| `你已经 X 天没打开了` | 产生被监控感 | 默认不发此类通知 |

## 8. 落地顺序

1. 先锁定当前两类系统通知和权限拒绝文案，保持现有调度行为不变。
2. 再补充固定 locale 快照测试，至少覆盖简体中文、英文、德语和日语；重点检查宠物长名、备注为空、`1 年/2 年` 和通知换行。
3. 需要增加新通知类型时，先补“触发条件、去重 ID、关闭入口、空数据规则”，再新增本地化 key。
4. 里程碑、照片数量、月度/年度回忆属于规划文案，待调度能力完成后再进入 `Localizable.xcstrings`。
