# ADR-0008：iOS V1.0 功能范围定案

## 1. 背景

迁移评估阶段（[PLAN.md](../../PLAN.md) §范围待确认清单）列出 5 项需产品对齐的范围决策：图片编辑器、家庭局域网备份、AI 写真/回忆视频、扫描增强（质量评分 + 重复分组）、iPad 适配。P0 验收标准明确要求「范围『待确认』项有明确结论（产品签字或显式延后）」，未拍板则 P0 无法收口。

[DESIGN.md](../../DESIGN.md) §10 此前的隐含默认为「编辑器 / 备份 / 评分后置 V1.x」，本文将其替换为正式产品决策。

## 2. 决策

| 项 | 结论 | 与默认建议对比 |
|---|---|---|
| 完整图片编辑器 | ✅ **进 V1.0**（完整迁移源端 `editor/` 约 30 文件） | 扩范围（默认建议后置 V1.x） |
| 质量评分 | ✅ **进 V1.0** | 扩范围（默认建议后置） |
| 重复分组 | ✅ **进 V1.0** | 扩范围（默认建议后置） |
| 家庭局域网备份 | ❌ 后置 V1.x | 采纳默认 |
| AI 写真 / 回忆视频 | ❌ V1.0 不做（无源端参照，需独立云方案） | 采纳默认 |
| iPad 适配 | ✅ **V1.0 支持**（iPhone + iPad） | 采纳默认 |

**净效果**：V1.0 在原 MVP 基线上**扩大**编辑器与扫描增强两项，仍**保持纯本地**（无云依赖、无备份服务）。

## 3. 影响与落地

### 3.1 扫描增强（影响 P2）
`ScanService` 扩展为「识别 + 评分 + 去重」三段式：

- **质量评分**：翻译源端 `QualityAnalyzer`（清晰度/构图/曝光等），写入 `Photo.qualityScore`。
- **重复分组**：翻译源端重复检测（CLIP embedding 相似度 + 视觉哈希），写入 `Photo.duplicateOf`。
- 扫描流程复杂度上升，需同步更新 [DESIGN.md](../../DESIGN.md) §7 扫描/导入边界说明与对应 XCTest。

### 3.2 完整图片编辑器（新增至 P4）
源端 `entry/src/main/ets/editor`（约 30 文件：裁切/旋转/滤镜/标注/马赛克/参数调节等）完整迁移：

- 新增 `Views/Editor/` + `ViewModels/Editor*` + 纯决策逻辑（裁切几何、滤镜矩阵、撤销/重做状态机）+ XCTest。
- 编辑器从「相册 / 大图查看」入口进入，产物回写沙盒（沿用 §7 唯一入库路径约束）。
- 归入 **P4「创作 + 编辑器」**里程碑，与拼豆图纸并行推进。

### 3.3 iPad 适配（跨 UI 里程碑）
SwiftUI 自适应布局（`NavigationSplitView`/`Layout`/尺寸类判断）跨 P2–P4 落地；**P5** 做 iPad 关键尺寸与分屏人工验证。

### 3.4 后置项边界
V1.0 **不建** `Services/Backup/`、**不引入**云服务依赖，保留 DESIGN.md §10「照片不离开设备」隐私承诺。备份/AI 写真仅在 V1.x 重新评估。

## 4. 风险与权衡

- **范围显著扩大**：编辑器（~30 文件）+ 扫描增强使 V1.0 工期增加。缓解：P1.3 拼豆核心与编辑器迁移可并行；编辑器优先翻译高价值能力（裁切/滤镜），标注/马赛克等可分批。
- **编辑器测试成本**：源端编辑器单测覆盖有限，需以纯决策逻辑（裁切/变换/撤销栈）为规格补充 XCTest，避免 UI 黑盒。
- **去重精度**：CLIP embedding 相似度阈值需在真机调参，初版可放宽阈值 + 提供「合并/保留」用户确认（对应源端 `matchRequired` 语义）。
