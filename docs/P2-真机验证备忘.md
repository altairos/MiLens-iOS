### 2.5 质量评分与重复分组（P2 扫描增强）

| 验证项 | 说明 | 风险 |
|---|---|---|
| `CoreImageAnalyzer` 真实 JPEG 解码 | `CGImageSourceCreateWithData` + `CGContext` 缩放到 256px 的灰度提取是否正确 | 中——Core Graphics 实现已写，但模拟器/真机解码行为可能有差异 |
| Laplacian 方差清晰度 | `computeSharpness` 对模糊照片 vs 清晰照片的方差差异是否符合预期（模糊 <500，清晰 >3000） | 中——纯逻辑单测用 mock 值；真机需验证真实 JPEG 的方差分布 |

| 重复分组标记 | 导入 3 张相似照片 → `findDuplicates` 后 `duplicateOf` / `isBest` 字段正确写入 | 中——纯逻辑 Union-Find 已单测；SwiftData `replaceDuplicateMarks` 原子替换需真机验证 |
| fire-and-forget 不阻塞 UI | `GalleryViewModel.triggerQualityAnalysis` 后台运行时网格滚动/操作是否流畅 | 中——`Task {}` 异步执行，但批量解码可能占用 CPU |
| pHash 补算时机 | 导入时 `ImportService` 不计算 pHash，由 `QualityScorer` 补算——验证补算后的 `phash` 非空 | 低——逻辑已单测（`testFillsPHashWhenMissing`） |

| 类型 | 协议 | 依赖 | 优先级 |

## 5. 真机验证操作清单

> 在 Mac + iPhone（iOS 17+）上按以下步骤逐项验证。

### 5.1 环境准备

```bash
# 1. 克隆并生成工程
git clone https://github.com/altairos/MiLens-iOS.git
cd MiLens-iOS
xcodegen generate

# 2. 打开 Xcode
open MiLens.xcodeproj

# 3. 选择 iPhone 真机（iOS 17+），配置开发者签名
```

### 5.2 测试恢复

```bash
# 移除 ScanServiceTests / ImportServiceTests / QualityScorerTests 的 setUp 跳过标记后：
xcodebuild -project MiLens.xcodeproj -scheme MiLens \
  -destination 'platform=iOS,name=YOUR_IPHONE' test
```

三组 SwiftData 集成测试（30 用例）共享同一崩溃模式，建议在 Mac 真机上一并恢复验证。

### 5.3 功能走查

1. **首次启动**：空相册 → 点击「开始扫描」→ 授权 Photos → 等待扫描完成弹窗
2. **导入**：扫描完成弹窗 → 点「导入 N 张照片」→ 验证照片出现在网格
3. **大图查看**：点网格照片 → 双击放大 → 捏合 → 平移 → 返回
4. **多选**：工具栏圆形按钮 → 勾选照片 → 返回
5. **分页**：导入 100+ 照片 → 快速滚动到底部 → 验证自动加载更多
6. **取消扫描**：启动扫描 → 点「取消」→ 验证不崩溃、不提交部分结果
7. **质量评分**（P2 增强）：导入照片后 → 通过 Xcode调试器/预览检查 `Photo.qualityScore` 和 `sharpness` 字段是否非零（后台 fire-and-forget，扫描/导入完成后数秒内完成）
8. **重复分组**（P2 增强）：导入 2–3 张相似照片（连拍/裁切版）→ 检查 `Photo.isBest` / `duplicateOf` 字段：其中 1 张 `isBest == true`，其余 `duplicateOf` 指向 best 的 UUID
9. **pHash 精度**（P2 增强）：导入一张清晰照片 + 一张模糊版 → 检查两者 pHash 汉明距离是否 ≤ 8（相似）；再导入一张完全不同的照片 → 检查距离是否 > 16

### 5.4 性能验证

```bash
# Instruments → Core Animation：网格滚动帧率
# Instruments → Allocations：大图库（5000+）内存峰值
# Instruments → Time Profiler：CLIP 模型首次加载延迟
# Instruments → Time Profiler：QualityScorer.computeAllQualityScores 批量解码 + 分析 100 张的耗时
# Instruments → Time Profiler：QualityScorer.findDuplicates Union-Find O(n²) 在 500+ 候选下的 CPU 时间
# Instruments → Allocations：CoreImageAnalyzer 批量解码时 CGContext 灰度缓冲（256² + 8²）内存峰值
```

## 6. 已知差距（与源端对比）

| 源端功能 | iOS V1.0 状态 | 说明 |
|---|---|---|
| 扫描 pause/resume | ❌ 未实现 | 源端 `PhotoScanner.pauseScan/resumeScan`；iOS V1.0 只支持 cancel |
| PetMatcher 自动归属 | ❌ 未实现 | 依赖 CLIP embedding（ADR-0007 方案 A），待 Core ML 模型就绪 |
| 质量评分 | ✅ 已实现 | [ADR-0008](adr/0008-v1-scope-decision.md)；`QualityScoringLogic` 纯公式 + `CoreImageAnalyzer` Core Graphics 实现 + `QualityScorer` 编排 + 13 用例单测。待真机验证真实 JPEG 的 Laplacian 方差分布与 pHash 精度（§2.5） |
| 重复分组 | ✅ 已实现（pHash） | [ADR-0008](adr/0008-v1-scope-decision.md)；`DuplicateGroupingLogic` Union-Find + `PerceptualHashLogic` aHash + 9 用例单测。当前用 pHash 视觉哈希，不依赖 Core ML；待 CLIP 模型就绪后可增强为 embedding 相似度 |
| EXIF GPS / 地点 | ✅ 纯逻辑已落地 | `PhotoMetadataLogic` 有解析逻辑 + `EditorExifPolicy` 有 GPS 解析；`ImportService` 接入待真机 |

| 缩略图缓存（LRU） | ❌ 未实现 | 源端 `ThumbnailCache`；iOS 当前每次 `UIImage(contentsOfFile:)` 现读 |
| 图片编辑器 | ✅ 纯逻辑层已落地 | [ADR-0008](adr/0008-v1-scope-decision.md)；MiLensKit Phase 1-2 完成（8 文件 53 用例），Phase 3 App 层 UI 需 Mac |
