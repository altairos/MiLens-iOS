# MiLens UI Rework 系统审计

审计日期：2026-08-08

## 1. 审计范围

本次不评价当前 SwiftUI 完成度，重点检查产品叙事、V1 范围、信息架构、首次使用闭环、视觉语言、设计系统、平台适配和设计可交付性。事实来源为 `DESIGN.md`、`PLAN.md`、`MIGRATION_ASSESSMENT.md`、旧版 `UI-DESIGN.md`、页面原型与 ADR-0008。

## 2. 总结

旧规范有一个正确的核心方向——“照片是主角的中性画廊”——但不适合直接落地。它更接近审美宣言与关键页 moodboard，未形成可以被产品、设计、开发和 QA 共同验收的系统。

建议不是推翻品牌，而是把它从“暖色、文楷、爪印、圆角卡片”的风格集合，重构为“照片证据 + 时间结构 + 用户控制”的产品语言。修订后的执行规范见 [UI-DESIGN.md](../UI-DESIGN.md)。

## 3. 阻断问题

### P0-1 能力承诺与 V1 范围冲突

页面原型和旧付费墙仍展示 AI 写真、回忆视频、“认识每一只宠物”等承诺，但 ADR-0008 明确 V1 不做 AI 写真和回忆视频，当前扫描能力也不等同于可靠的个体识别。继续沿用会造成产品误导、付费权益不可交付和 App Store 素材风险。

处置：V1 创作只保留拼豆与宠物卡片；编辑器作为照片上下文工具；所有 AI 文案改为概率性、可纠正的“候选发现”。

### P0-2 首次使用没有完成价值闭环

旧流程是“扫描发现 → 创建宠物 → 完成”，但扫描只筛选、不入库，建档也没有把候选照片确认、导入并归档。用户在情绪峰值之后可能进入一个空档案。

处置：增加候选确认与归档步骤；引导完成后直接打开包含真实照片的第一份档案。无权限、无候选或扫描失败时提供明确替代路径。

### P0-3 主动作色不可访问

旧规范把 `#FD8663` 同时作为品牌色、白字主按钮背景和选中态。计算结果：白字/珊瑚约 2.40:1，珊瑚/浅背景约 2.26:1，均不足以承担常规文字或关键交互。

处置：保留 `BrandCoral`，新增更深的 Light 动作色 `#BC4727`；Dark 动作色使用 `#E8845F` 并配暖黑文字。普通正文目标 4.5:1，非文字关键控件目标 3:1。

### P0-4 付费墙内容不可作为规格

旧稿硬编码月/年价格、试用天数和折扣，并把未上线能力写进权益。价格与试用必须来自 StoreKit，权益必须先有产品矩阵与可验证实现。

处置：付费墙按触发场景设计，动态展示产品信息；在权益矩阵冻结前不定稿营销文案。

## 4. 高优先级问题

### P1-1 品牌表达过度依赖通用符号

大号爪印、Emoji、珊瑚色和圆角卡片很亲切，但同类宠物 App 大量使用，不能构成独有识别；同时会把“生命档案”拉向轻量工具或儿童化产品。

处置：真实照片优先；建立“记忆标记”（圆点、时间线、日期标签）作为贯穿语言；大型 SF Symbol 仅用于功能空态。

### P1-2 字体系统有三种竞争声线

霞鹜文楷、Fraunces、SF/PingFang 同时承担页面层级，容易让情感字体变成装饰噪音，并增加中英文缺字、Dynamic Type 和视觉一致性成本。

处置：系统字体承担操作界面；文楷每屏最多用于一个 Hero 或 Story 标题；Fraunces 退出常规界面，仅保留给英文营销/wordmark。

### P1-3 页面规范不可直接交付

旧稿描述了 Hero、网格和卡片，但没有完整定义组件状态、权限状态、失败路径、横竖屏、大字号、High Contrast、Reduce Motion 和 iPad 重排。

处置：新规范加入响应式网格、十个核心组件、页面状态和统一验收门禁。

### P1-4 首页数据规则缺失

“今日最佳”和“一年前的今天”只有概念，没有来源、无今日照片、多宠物、重复照片、无备注等回退规则。设计很容易只在假数据主状态下成立。

处置：定义 newUser、hasPhotosNoToday、hasToday、hasAnniversary、multiplePets 五种首页内容态，Hero 规则与质量/重复信息联动。

### P1-5 iPad 被当成放大的 iPhone

旧规范只写了尺寸检查，没有给出 Sidebar、Inspector、Split View 和可变窗口的结构决策。

处置：宠物/设置采用 Sidebar + Detail；相册采用可变网格；创作与编辑器采用 Canvas + Inspector。

## 5. 中优先级问题

- Tab 切换统一加动画和触感会造成频繁干扰，改为系统行为。
- “付费 App 必须更大留白/必须衬线”等表述是审美偏好，不是可验证原则，已改为内容密度与任务优先级规则。
- 相册 hero transition 不能只写 iOS 18 API，需定义 iOS 17 fallback。
- 低质量、重复和 AI 结果需要允许用户纠正，不应以系统判断覆盖用户意图。
- 强制勾选隐私政策增加首次启动摩擦，也不等同于有效的权限说明；改为清晰链接与按需授权。
- “我的”在无账号系统下不得伪造个人中心结构，应作为本地数据、隐私与购买控制中心。

## 6. 保留项

- “找回被遗忘的它，保存属于你们的一生”的叙事。
- 首页以一张真实照片建立情绪，而不是功能宫格。
- 暖白/暖黑画廊画布。
- 珊瑚作为稀缺品牌记忆点。
- 时间线式宠物档案与照片优先的相册。
- 创作作为商业化入口，但必须服从真实范围和上下文。

## 7. 推荐决策顺序

1. 产品先冻结 V1 能力、免费/Pro 权益和首次导入规则。
2. UX 用低保真原型验证“首次导入闭环”和“日常回忆闭环”。
3. 视觉完成动作色、字体边界、记忆标记与核心组件。
4. 用真实照片集制作关键页高保真稿，并覆盖异常状态。
5. 通过设计验收门禁后再开始 SwiftUI 页面实现。
