# 伙伴生命档案设计

最后核对：2026-08-10

本文件定义“确认伙伴后形成长期生命档案”的产品模型、页面结构和 V1 实施边界。视觉 token 与通用状态以 [UI-DESIGN.md](../UI-DESIGN.md) 为准，技术分层以 [DESIGN.md](../DESIGN.md) 为准。

## 1. 产品判断

MiLens 的档案不应只是“宠物详情 + 照片列表 + 日期事件列表”。它是一个可以被用户确认、解释、回看和继续补写的长期对象。

当前体验需要同时承载三种时间：

1. **日历时间**：照片和事件实际发生的日期。
2. **相处时间**：年龄、来到家第几天、相伴年数等关系指标。
3. **记忆时间**：用户认为重要的起点、转折、习惯和故事。

系统可以整理前两种时间，并提出候选记录；第三种时间必须由用户确认或补充，不能由 AI 擅自替用户编写生命故事。

## 2. 档案对象模型

档案由四类内容组成：

| 内容 | 作用 | 可靠来源 |
|---|---|---|
| 身份摘要 | 名字、物种、性别、生日、领养日、封面 | 用户填写/确认 |
| 重要记忆 | 来到家、生日、第一张照片、用户备注等锚点 | 用户记录或明确日期推导 |
| 照片记忆 | 某日或某段时间的代表照片与照片组 | 照片日期 + 用户确认 |
| 作品记录 | 拼豆图纸、伙伴卡片、编辑产物及其来源照片 | App 生成记录 |

档案页需要同时提供“看”和“继续整理”两类动作：

- 看：查看置顶记忆、章节、时间线、照片和作品。
- 整理：添加记忆、关联照片、置顶、设为档案起点、更正日期、合并重复记忆。

## 3. 页面结构

### 3.1 伙伴档案首页

顺序固定为：

```text
肖像 Hero / 身份
→ 档案摘要：照片 / 记录 / 重要日子 / 相处天数
→ 置顶记忆 / 档案起点
→ 最近记忆
→ 照片分段：全部 / 待整理 / 作品
→ 成长时间线入口
→ 添加一条记忆
```

年龄和相处天数放在身份区，统计区优先表达档案积累量，不把页面做成纯资料卡。

### 3.2 时间线

时间线不是无限滚动的单条事件流，而是由以下单元组成：

- **相处章节**：用户可以给一段日期范围命名；未命名时只显示日期范围，不自动臆测阶段名称。
- **重要日子**：生日、领养日、用户确认的纪念日。
- **照片记忆组**：同日或同段时间的代表照片，显示照片数量和日期。
- **用户记录**：标题、日期、正文、关联照片。
- **作品记录**：由某张照片或某段记忆生成的作品。

节点必须同时区分形状、标签和内容结构，不得只用颜色区分。系统推导的内容明确标注来源，例如“根据日期生成”“照片回忆”；用户记录明确标注“你记录的”。

### 3.3 添加记忆

从伙伴档案、时间线和照片详情均可进入“添加一条记忆”。最小表单包括：

- 标题
- 日期或日期范围
- 一句话/备注
- 关联照片（可选）
- 是否置顶（可选）

保存后内容进入时间线，并可以被编辑、取消置顶或移除关联。添加记忆不要求用户选择复杂事件类型。

### 3.4 照片与档案的连接

照片详情的档案相关主动作是“加入记忆”，而不是只提供编辑、拼豆和分享。用户可以：

- 加入已有记忆
- 新建记忆
- 设为封面或代表照片
- 补充备注

照片仍然保留在相册中；加入记忆只是建立档案关联，不复制或删除系统相册原图。

### 3.5 年度回看

纪念提醒和首页回忆可以进入同一个年度回看入口：

```text
去年今天 → 今年今天
→ 查看代表照片
→ 添加今年的照片
→ 写下一句话
```

这是静态照片与文字的回看能力，不承诺 AI 写真或回忆视频。年度回看结果可以作为时间线中的一条照片记忆或用户记录保存。

## 4. 视觉层级

- Hero 表达“这是哪个伙伴”；置顶记忆表达“为什么重要”；时间线表达“如何一路走到今天”。
- 照片记忆组使用较大代表图，不能全部退化为右侧小缩略图。
- 重要日子、照片组、用户记录、作品记录使用不同的标记形状和标签。
- 珊瑚色只用于当前节点、选中态和添加动作；档案内容本身由照片和文字提供色彩。
- 普通时间线优先使用留白、分隔线和纵向主轴，不把每条记录都包成独立圆角卡片。

## 6. 验收标准

- 新建伙伴后，用户可以完成至少一条有日期、有文字或照片关联的记忆。
- 照片详情可以进入已有记忆或新建记忆，且不会暗示删除系统相册原图。
- 时间线中用户记录、系统推导、照片记忆和作品记录可被非颜色方式区分。
- 置顶记忆和档案起点在档案首页首屏可发现。
- 年度回看可以回到同一条时间线，并继续补充当前年份内容。
- 未授权、无照片、无记忆和失败状态都提供明确的继续整理路径。
